# WangDoKu「1 vs 1」對戰模式 — 玩法與開發規格

本文件說明 WangDoKu 的 1 vs 1 對戰規則與流程，供開發網路對戰版本使用。數字與規則皆與目前的網頁版一致。

## 一、遊戲概述

WangDoKu 是狗狗主題的邏輯謎題（與 Star Battle / LinkedIn Queens 同類）。「1 vs 1」是兩名玩家在**同一張棋盤**上即時競速：**誰先放對 4 隻狗誰就贏，放錯 1 隻立刻輸**。

## 二、基本謎題規則（勝負判定的基礎）

- 棋盤為 **7×7**，分成 7 個相連的顏色區塊。
- 正解中：每個顏色區塊、每一行、每一列各恰好 1 隻狗，且任兩隻狗不相鄰（含斜角）。
- 題目保證**唯一解**，難度為「困難」（需用到一步反證等推理）。
- 因為唯一解，「某格放狗是否正確」＝「該格是否為解答格」，判定很單純。

## 三、對戰規則

1. **共享棋盤**：雙方看到同一張題目；任何一方放下的正確狗都會出現在雙方畫面上，並佔住該格。
2. **勝利條件**：先累積 **4 隻正確的狗**者獲勝（不需要解完 7 隻）。
3. **立即失敗**：放下一隻**不在解答格**的狗 → 該玩家立刻輸，對手獲勝。
4. **搶格**：已被任何一方佔住的格子不能再放、不能移除。雙方同時搶同一格時，以**伺服器先收到者**為準，後到者的操作無效（不算錯、不扣分）。
5. **❌ 標記是私人的**：玩家可在格子上畫 ❌ 當推理草稿，**只有自己看得到**，不計分、不影響對手、沒有對錯判定。
6. **單格顏色區塊（送分狗）**：若某顏色區塊只有 1 格，那格必定是狗。開局時系統**自動放上**，以金色標示，**雙方各得 1 分**（例如有 1 個單格區塊，雙方都從 1/4 開始）。
   - 若單格區塊數 ≥ 4（開局就會分出勝負），須**重新出題**。

## 四、對局流程

1. **配對**：建立房間 / 邀請連結 / 隨機配對。
2. **出題**：產生 7×7 困難唯一解題目。
3. **預放送分狗**：處理單格區塊，雙方分數同步加上。
4. **倒數**：雙方畫面同步顯示 **3 → 2 → 1 → Go!**（約 3 秒），倒數期間不能操作。
5. **比賽**：Go 之後開始計時，雙方自由作答。
6. **結束**：任一方達到 4 分、或任一方放錯 → 結束，雙方顯示結果卡（勝 / 負 / 放錯了）與最終比分。
7. **再戰**：雙方同意後開新局（新題目）。對戰中也有「重來」按鈕（需處理對手同意，或視為離開）。

## 五、操作方式（手機為主）

| 操作 | 效果 |
|---|---|
| 單點一下 | 空格 → ❌ |
| 在 ❌ 上 **1 秒內**再點一下（快速連點兩下） | 放狗（送出判定） |
| 在 ❌ 上**超過 1 秒**才再點 | 不放狗，清回空格（防誤觸） |
| 長按 / 桌機右鍵 | 直接放狗（送出判定） |
| 點已被佔住的狗格 | 無作用 |

> 因為放錯會直接輸，「放狗」必須是有意的動作，這是刻意設計。

## 六、畫面需求

- **比分列**：`你 x/4 ｜ ⏱ 已過時間 ｜ 對手 x/4`，時間置中、Go 之後開始跑、結束時定格。
- **狗的顏色標示**：自己的狗＝藍框、對手的狗＝紅框、送分狗＝金框；放錯的那格以紅底標出。
- **對手狀態提示**：對手分數下方的紅線左右滑動，表示「對手正在思考 / 在線中」；斷線時停止並顯示斷線。
- **結果卡**：勝負標題、雙方比分、「再戰一場」。

## 七、網路對戰的技術要點

1. **伺服器權威**：解答只能存在伺服器，不能傳給任何客戶端，否則可直接作弊。客戶端只拿到色塊配置（`regions`）。
2. **出題也在伺服器**：題目最好由伺服器產生；若由某一方客戶端產生再上傳，那一方就知道答案。
3. **放狗流程**：客戶端送 `place(r, c)` → 伺服器判定：
   - 格子已被佔 → 回 `rejected`（無效，不懲罰）
   - 是解答格 → 記為該玩家、加分、**廣播**給雙方；若達 4 分 → 廣播結束
   - 不是解答格 → 該玩家判負、廣播結束
4. **❌ 標記不上傳**（純客戶端狀態），省流量也確保私密。
5. **時間同步**：倒數與計時以伺服器下發的「開始時間戳」為準，避免各端時鐘不一致。
6. **延遲**：放狗結果以伺服器回應為準；客戶端可先顯示「送出中」，收到確認再上色。
7. **斷線**：對手斷線超過一段時間（建議 15–30 秒）→ 判在線方勝；短暫斷線可重連回到原局面（伺服器保存盤面與分數）。
8. **同時達標**：兩人「同時」湊到 4 分時，以伺服器處理順序決定，先處理者勝。
9. **題目傳遞**：可沿用現有的題目壓縮格式（網址參數 `?p=`，7×7 約 20 字元）傳色塊；解答由伺服器保存。

## 八、可調參數（現行預設）

| 參數 | 預設值 |
|---|---|
| 棋盤大小 / 難度 | 7×7 / 困難 |
| 勝利所需正確狗數 | 4 |
| 連點判定時間 | 1000 ms |
| 開賽倒數 | 3, 2, 1, Go!（各約 0.8 秒） |
| 單格送分狗上限 | < 4（否則重新出題） |

  - 目前的線上房間：`js/multiplayer.js`（Supabase RPC：`create_match`、`join_match`、`get_match`、`play_match_move`、`leave_match`）。放狗已由伺服器判定，但題目與解答是由開房的一方在客戶端產生後上傳（`p_solution`），所以開房者理論上知道答案。正式版建議改成第七節第 2 點的做法。
